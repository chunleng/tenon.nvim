## Process
1. If the user has not yet provided the subject, ask what the reference document should cover
2. Scan existing documentation for a document that already covers the subject
3. If an existing document is found, check whether it is auto-generated (markers like "generated by" or "do not edit", or a build step that generates it). If it is, report the finding to the user and end the choreo
4. Explore the repository to ground the reference:
   - Locate the code relevant to the subject
   - Identify the public items to document (functions, commands, options, entities) and their factual details: signatures, parameters, defaults, allowed values
   - If an existing document covers the subject, read it to determine what to keep and what to update
5. If information needed for the reference cannot be determined from the user's input or the code, ask the user, then go back to step 4
6. Determine the reference kind: API, CLI, configuration, data model, or other

## Choreo Move Artifact
```yaml
subject: "what the reference document covers"
kind: "api|cli|configuration|data_model|other"
doc_path: "path of the reference document to create or update"
items:
  - "public items to document, e.g. functions, commands, options, entities"
```
