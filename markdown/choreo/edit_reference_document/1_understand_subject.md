## Process
1. If re-entered from Write Reference because `format` was absent, skip to step 8, reusing the existing subject context
2. If the user has not yet provided the subject, ask what the reference document should cover
3. Scan existing documentation for a document that already covers the subject
4. If an existing document is found, check whether it is auto-generated (markers like "generated by" or "do not edit", or a build step that generates it). If it is, report the finding to the user and end the choreo
5. Explore the repository to ground the reference:
   - Locate the code relevant to the subject
   - Identify the public items to document (functions, commands, options, entities) and their factual details: signatures, parameters, defaults, allowed values
   - If an existing document covers the subject, read it to determine what to keep and what to update
6. If information needed for the reference cannot be determined from the user's input or the code, ask the user, then go back to step 5
7. Determine the reference kind: API, CLI, configuration, data model, or other
8. If the kind is **Other**, determine the document format (mandatory sections to include in the document):
   a. Check for a similar document - one covering a similar kind of subject - and borrow its format. Sibling documents in the same group as the reference document are likely candidates; check them first
   b. If no similar document is found, propose a good default format
   c. Confirm the chosen format (borrowed or default) with the user; adjust it per their feedback

## Choreo Move Artifact
Fill in the artifact in full, including on re-entry.

```yaml
subject: "what the reference document covers"
kind: "api|cli|configuration|data_model|other"
doc_path: "path of the reference document to create or update"
items:
  - "public items to document, e.g. functions, commands, options, entities"
format:
  - "mandatory sections to include in the document; required when kind is other, optional for other kinds"
```
